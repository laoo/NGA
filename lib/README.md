# The library

What the tool ships as source rather than compiles in: a storage driver per
mechanism, a decoder per format over any driver's stream, the machine's own
software where it occupies memory a program has to work around, and a machine
variant that names all three. A variant here describes the machine and not one
program's use of it, so it declares what the hardware has whether or not a
given Project writes it. A Project
reaches a file here by naming it in `modules` or `include` as it names one
of its own; a path that is not beside the naming document is looked for
here.

| File | What it is |
|---|---|
| `atari/130xe.ngp` | An Atari 130XE: the four extended Banks as a unit set and the storage, the Window `ext` that shows them over `$4000-$7FFF`, the Window `os` whose states are the ROM and the RAM beneath it, every Region of the address space, `PORTB`, and the three Modules below listed as `resident`. It reserves what a DOS of the 2.x family holds, since it takes no Container but the `.xex` a DOS loads; a Project gets the machine with `include "atari/130xe.ngp"` and declares for itself only what it wants beyond that — a register by name, or a DOS that takes more. |
| `atari/800xl.ngp` | An Atari 800XL with a double-density disk drive: no banking, so storage is the diskette's sectors, 256 to a unit, and there is no unit set and no Window. Every Region of the address space, `PORTB`, and the three Modules below listed as `resident`. Its Containers are the `.atr` it boots and the `.xex` a DOS loads. A Project gets the machine with `include "atari/800xl.ngp"`. |
| `atari/cart.asm` | The driver for a XEGS cartridge's banks: the units are the Banks of the variant's `banks`, which the byte written to `$D5FF` brings into `$8000-$9FFF` — `switched` in the variant — and the stream is a pointer into that window that walks on to the next unit at its end. A state of `switched` **is** a Bank, so this driver holds no table of values where `portb.asm` holds one, and `show` is two instructions: the window has no named state to number before the Banks, and the board wires the byte written straight to the address lines above the window. The register is written and never read, so which bank is in is this driver's own byte. Needs the variant's Window `switched`, a unit set `banks` and storage that is it; `copy` reads the window directly, as PORTB's does. |
| `atari/charsets.asm` | The Atari's two codes for the same letters, as Charsets: `atascii`, what the character I/O takes, with the graphics characters where an ASCII machine keeps its control codes and `\n` mapping to `$9B`; and `screen`, what the display reads out of screen memory. The graphics are written as the Unicode their glyphs are drawn as, inverse video included — the blocks and triangles have complements and the letters have negative squares — so a picture drawn in the source is the picture the machine draws. Emits nothing; both variants list it, so a Project that includes one has both by name. |
| `atari/xegs128.ngp` | An Atari 800XL holding a 128 KB XEGS cartridge: sixteen banks of eight kilobytes, of which the last is the fixed part the CPU always sees at `$A000-$BFFF` and the other fifteen are the storage the byte written to `$D5FF` brings into `$8000-$9FFF`. The window has **no base** — there is no memory under the banks to come back to, so a `.with` switches and leaves it switched (0217) — and its ranges are in no Region at all, so only a Pane or storage stands there. Its Container is the `.car` and nothing else, and a cartridge needs no DOS, so the whole of RAM below `$8000` is the program's, `$0700` included. A Project gets the machine with `include "atari/xegs128.ngp"`. |
| `atari/disk.asm` | The driver for a double-density diskette: a unit of storage is 256 sectors of 256 bytes, so the unit is the sector number's high byte and the offset is the rest, and unit zero begins at sector 4, the first after the boot record. It reads a sector through the OS's own disk handler at `DSKINV`, so it knows no register and no drive; the stream is that sector in a buffer and a position in it, carrying into the next sector at its end. It names no Window, so `stream`, `show` and `showAt` are not declared. Needs storage by count whose `size` is 65536, and the `.atr` Container — see 0211. |
| `atari/os.asm` | The Atari OS as a Module: four Sections that hold no bytes, pinned over its zero page, its variables and its two ROM ranges, each `root`, exporting the names a program reaches it by — `RTCLOK`, `SDMCTL`, `SDLSTL`, `SDLSTH`, `SHPDVS`, `CH`, `SETVBV`, `XITVBV`. Listed in `resident` by the variant; see 0051. |
| `atari/mariacel.ngp` | An Atari 800XL holding a **MariaCEL** cartridge: an FPGA board on the parallel bus with a sprite blitter, a video output of its own and 32 MB of SDRAM behind two windows of sixteen kilobytes. Either window can show anything the board has, so the variant makes the choice a Window needs: `cel8000` shows the storage and `cel4000` the blitter's five BRAM blocks, which is what the board's own programs do. Storage is **250 Banks and not 2048** — a state travels in a byte — so 4 MB of the 32 is the tool's and what lies above it is the program's own, reached by writing `RAMMAP8000L/H` by hand. `$8000-$BFFF` is in no Region, as a XEGS cartridge's window is; `$4000-$7FFF` is `ram`, since the machine's own memory is under it. It declares the registers the board's example programs write and no more, and needs BASIC switched off for its high window's base state to be the RAM it promises. Its Container is the `.xex` a DOS loads. |
| `atari/mcel.asm` | The driver for that board: the two RAMMAP windows, and the SDRAM behind the one at `$8000` as storage. It declares **`init`** — the one Container-called role there is (0227) — because the board answers at none of its addresses until `PDVREG` carries its identifier, so until then a write to RAMMAP is a write to nothing and nothing reports it. A state of `cel8000` below the count of `sdram` is a Bank and the block is one more than it, block zero being what `RAMMAP = 0` already means; the states of `cel4000` are a table and not arithmetic, since bit 7 of the high byte is what takes the window off SDRAM. Exports the `CELCTL` masks and the palette bank numbers, with the two rules that go with them — the obligatory level mask, and no read-modify-write. Needs the variant's Windows, its `register` list, a unit set `sdram` and storage that is it. |
| `atari/mceltables.asm` | The blitter's two input tables as Sections in the variant's Panes: `sprList`, 5120 bytes of sprite records, and `texTab`, 4096 of texture descriptors, each pinned to the state of `cel4000` that shows it. Neither holds bytes and neither could — a Pane pinned to a named state has no loader to come from, and BRAM is not memory a Container writes — so the program fills them through the window. `root`, since the blitter reads them with no Reference; not `foreign`, since the CPU reads and writes every byte. Beside `sprList` stand the seven bytes the viewport and the collision scan answer at, which are registers of the blitter that happen to be inside a window rather than beside `CELCTL`, and are therefore here and not in the variant's `register` list. What a record holds is the board's documentation and is deliberately not repeated. |
| `atari/portb.asm` | The driver for extended memory behind `PORTB`: it streams through the variant's Window `ext`, shows a state of `ext` and of `os` on request — the PORTB value per state is its own table, trimmed to the variant's `extension` by a macro — and `copy` reads the window directly. Its roles are macros: `open`, `read`, `show` and `showAt` call a procedure each, the OS Window's two are inline. Needs the variant's `register PORTB`, its Windows `ext` and `os`, a unit set `extension` and storage that is it. |
| `lynx/lynx.ngp` | An Atari Lynx, as the CPU sees it: 64 KB of RAM, the two pages Suzy and Mikey answer at, the boot ROM's range `reserved` and the four bytes above it that nothing reads left as memory, and 177 of the machine's registers by name. `cpu "65sc02"`, since the Rockwell bit instructions are the second revision's alone. No Window — nothing here is switched while it runs — and no storage, which a cartridge is and which `lynx/cart.asm` will reach. Why the map is taken to hold one value, and why the ROM is a Region and not a Module, is 0219. |
| `lynx/rom.asm` | The boot ROM's one entry this tool wants: `romSetPage = $FE00`, which shifts eight bits of `A` into the cartridge's address register and leaves the counter released. An address and a contract in a comment, as the Atari's `SETVBV` is — the ROM itself is the variant's `reserved` Region. |
| `lynx/screen.asm` | The buffer the display is given: 8160 bytes at `$E000`, `align 4`, `root`, `foreign`. It reaches `$FFDF`, through the pages the CPU reads as hardware and the display reads as memory, which is what `foreign` is for; the CPU reaches `$E000-$FBFF` of it and no Payload can land there. |
| `lynx/screen2.asm` | The second buffer, 8160 bytes at `$C000`, for a program that draws into one while the display reads the other. Wholly memory both masters agree on, so the CPU may write every byte and a Payload may land in it. |
| `lynx/collide.asm` | The buffer the sprite engine builds collisions in, 8160 bytes at `$A000`, `foreign` for the same reason and with no `align`, since it is the display address register alone that rounds an address down. |
| `pet/3032.ngp` | A Commodore PET 3032: a 6502, thirty-two kilobytes of RAM, the display's page at `$8000`, the I/O the IEEE-488 port is split across, and the three Modules below listed as `resident`. The ROMs are **`reserved` and not `rom`** — `rom` is where a Section of ours may stand, which is true of a cartridge and false of a machine whose ROM was in it first (0224). `$0200` to `$040D` stands in no Region: it is RAM, but RAM a `.prg` cannot carry, since `LOAD` puts the block at `$0401` and the line of BASIC that enters the program is there. Its Containers are the `prg` and the `d64`, which is the same program on a diskette whose other sectors a Transition reads. A Project gets the machine with `include "pet/3032.ngp"`. |
| `pet/kernal.asm` | What the PET's ROM keeps in RAM, as Sections holding no bytes, and the addresses a program calls it at. This is a machine whose interrupt handler the program has taken over, so what is reserved is what the kernal's **disk path** touches — measured at twelve bytes of zero page, five of them the caller's own — and seven more the kernal's handler may write in the window between the `SYS` and the program's own `sei`. Every address is specific to `kernal-2.901465-03`; the bodies of `OPEN` and `CLOSE`, which machine code enters past the BASIC parameter parser, are published wrongly for other sets and land mid-instruction here. |
| `pet/screen.asm` | The display's memory: 1024 bytes at `$8000`, `root`, a thousand of them shown. Not `foreign`, unlike a Lynx's buffer — nothing of the hardware answers at these addresses, so the CPU may write every byte. The Label is `screenRam`, since `screen` is the name of the Charset these bytes are read as. |
| `pet/charsets.asm` | The PET's two codes for the same letters, as Charsets: `petscii`, what the ROM's character output takes, which over the range a program prints is ASCII but for the pound sign and the two arrows; and `screen`, what the video circuit reads out of the display, where `@` is zero and a letter is not what ASCII makes it. The **graphics halves are not written**: each would have to be read off the character generator and matched to the Unicode its glyph is drawn as, as the Atari's was, and until then a literal of one is refused by name. Emits nothing. |
| `pet/disk.asm` | The driver for a Commodore diskette, which the program reads over the IEEE-488 bus itself. A unit is a **track** and the offset's high byte is the sector, so the three bytes the model addresses storage with are the two numbers `U1` takes and `open` does no arithmetic on them. It says `.driver span none`, so nothing ever crosses a track and it needs to know **nothing** of the surface: not which tracks are long, not where the directory is, not which track follows which. The OPEN sequence is by hand — the ROM's own begins with the BASIC parameter parser, which reads its arguments out of BASIC text — success is read from the count of open files at `$AE` and not from the carry, and EOF is bit **6** of `STATUS`. The data path is the ROM's handshake with the timeout, the EOI test and the channel dispatch taken out. Names no Window, so `stream`, `show` and `showAt` are not declared. |
| `pet/d64.ngp`, `pet/d80.ngp`, `pet/d82.ngp` | Storage on a diskette of that surface: 36 units of 5376 bytes, 78 of 7424 or 155 of 7424, the driver above and `zx0`. The unit's number is the track's, so unit zero is no track, the directory's track is the disk's and — on the larger two — so is the track its map has to itself. `size` is the **widest** track and therefore a stride, since what a narrower one does not have is held against every image. A Project includes the one whose surface it named in `container`, and the two are checked against each other (`NGA1238`). |
| `lynx/cart.asm` | The driver for the cartridge, which is the one medium here that is not in the address space: a page is shifted into an address register eight bits at a time and a counter walks it, so there is no Window and `stream`, `show` and `showAt` are not declared. A unit of storage is a **page** and the model's unit *i* is page *i+1*, page zero holding the bootstrap — a constant this file and the Container both hold, as the diskette's sector four is. It says `.driver seek forward`, an offset being reachable only by reading up to it, and `open` therefore reads on from where the stream stands wherever the page is the one wanted and the offset is ahead of it. Needs `lynx/rom.asm` for the routine that shifts a page in, and one of the four documents below for its page size. |
| `lynx/cart64k.ngp`, `lynx/cart128k.ngp`, `lynx/cart256k.ngp`, `lynx/cart512k.ngp` | Storage on a board of that size: 255 units of its page, the driver, and `zx0`. A Project includes the one whose geometry is the board it names in `container`, and the two are checked against each other (`NGA1237`). |
| `lynx/screen.ngp`, `lynx/screens.ngp` | One display buffer, or two, under the one name `screens` — so that a Project changes how many it has by changing which document it includes. **Include one of the two and never both**: they declare the same Module, and twice over it is the same Section twice. |
| `stream/rle.asm` | The `rle` decoder over a driver's stream, read through `nga.read`. |
| `stream/zx0.asm` | The `zx0` decoder over a driver's stream, read through `nga.read`. |

Everything here goes into the program a Project builds, so it is licensed

Every file here is held to what it claims by the test suite of the repository
it is developed in: the Container built with it is loaded into a machine and
every Transition it takes is run on a 6502.
