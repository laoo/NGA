# The library

What the tool ships as source rather than compiles in: a storage driver per
mechanism, a decoder per format over any driver's stream, the machine's own
software where it occupies memory a program has to work around, a machine
variant that names all three, and the storage that goes beside a variant. A
variant here describes the machine and not one program's use of it, so it
declares what the hardware has whether or not a given Project writes it. It
declares no storage: a program that loads anything during a run includes the
storage document beside it, and one that does not leaves it out — see
0234. A Project
reaches a file here by naming it in `modules` or `include` as it names one
of its own; a path that is not beside the naming document is looked for
here.

| File | What it is |
|---|---|
| `atari/130xe.ngp` | An Atari 130XE: **five Banks** as a unit set — the four of extended memory and, last, the machine's own memory under the Window, since no Window has a base (0229) — the Window `ext` that shows them over `$4000-$7FFF`, every Region of the address space, `PORTB`, and the OS and the driver below listed as `resident` — not BASIC, which a program that wants it lists itself. The driver is here and not with the storage because it also shows a Pane's Bank and switches the ROMs. It reserves what a DOS of the 2.x family holds, since it takes no Container but the `.xex` a DOS loads; a Project gets the machine with `include "atari/130xe.ngp"` and declares for itself only what it wants beyond that — a register by name, or a DOS that takes more. It names the RAM the OS ROM covers `underOsLow` and `underOsHigh`, for a Section's `in`. Its Holders are `dlist`, `dli`, `vbi`, `vbd`, `nmi`, `irq`, `chbase`, `pmbase` and `dosini` (0247, 0248). |
| `atari/extension.ngp` | Storage for `atari/130xe.ngp`: the Banks of its unit set `extension`, and `zx0` listed as `resident`. A Project includes it beside the machine. |
| `atari/800xl.ngp` | An Atari 800XL: no banking, so there is no unit set and no Window. Every Region of the address space, `PORTB`, and the OS and the Charsets listed as `resident`. Its Containers are the `.atr` it boots and the `.xex` a DOS loads. A Project gets the machine with `include "atari/800xl.ngp"`. It names the RAM the OS ROM covers `underOsLow` and `underOsHigh`, for a Section's `in`. Its Holders are `dlist`, `dli`, `vbi`, `vbd`, `nmi`, `irq`, `chbase`, `pmbase` and `dosini` (0247, 0248). |
| `atari/disk.ngp` | Storage for `atari/800xl.ngp` on a double-density diskette: the sectors from the fourth, 256 to a unit, and the driver below and `zx0` listed as `resident`. A Project whose Container is the `.atr` includes it beside the machine. |
| `atari/roms.ngp` | The ROMs of `atari/800xl.ngp` switched through `PORTB`, for a program without storage: `atari/roms.asm` listed as `resident`, which a `final` Phase other than the entry keeps none of. A Project includes it beside the machine so that a Phase may do without the OS and keep what it needs under it; not beside `atari/disk.ngp`, whose driver is the program's one and reads through the OS. |
| `atari/cart.asm` | The driver for a XEGS cartridge's banks: the units are the Banks of the variant's `banks`, which the byte written to `$D5FF` brings into `$8000-$9FFF` — `switched` in the variant — and the stream is a pointer into that window that walks on to the next unit at its end. A state of `switched` **is** a Bank, so this driver holds no table of values where `portb.asm` holds one, and `show` is two instructions: the window has no named state to number before the Banks, and the board wires the byte written straight to the address lines above the window. The register is written and never read, so which bank is in is this driver's own byte. Needs the variant's Window `switched`, a unit set `banks` and storage that is it; `copy` reads the window directly, as PORTB's does. |
| `atari/charsets.asm` | The Atari's two codes for the same letters, as Charsets: `atascii`, what the character I/O takes, with the graphics characters where an ASCII machine keeps its control codes and `\n` mapping to `$9B`; and `screen`, what the display reads out of screen memory. The graphics are written as the Unicode their glyphs are drawn as, inverse video included — the blocks and triangles have complements and the letters have negative squares — so a picture drawn in the source is the picture the machine draws. Emits nothing; both variants list it, so a Project that includes one has both by name. |
| `atari/xegs128.ngp` | An Atari 800XL holding a 128 KB XEGS cartridge: sixteen banks of eight kilobytes, of which the last is the fixed part the CPU always sees at `$A000-$BFFF` and the other fifteen are the storage the byte written to `$D5FF` brings into `$8000-$9FFF`. There is no memory under the banks, so a `.with` switches and leaves it switched, as on every Window (0217, 0229), and its ranges are in no Region at all, so only a Pane or storage stands there. Its Container is the `.car` and nothing else, and a cartridge needs no DOS, so the whole of RAM below `$8000` is the program's, `$0700` included. A Project gets the machine with `include "atari/xegs128.ngp"`. Its Holders are the 800XL's and `cartinit`, which the header hands its init routine to (0248). |
| `atari/disk.asm` | The driver for a double-density diskette: a unit of storage is 256 sectors of 256 bytes, so the unit is the sector number's high byte and the offset is the rest, and unit zero begins at sector 4, the first after the boot record. It reads a sector through the OS's own disk handler at `DSKINV`, so it knows no register and no drive; the stream is that sector in a buffer and a position in it, carrying into the next sector at its end. It names no Window, so `stream`, `show` and `showAt` are not declared. Needs storage by count whose `size` is 65536, and the `.atr` Container — see 0211. |
| `atari/osram.asm` | The memory the Atari OS keeps its variables in: two Sections that hold no bytes, pinned over its half of the zero page and over `$0200-$06FF`, each `root`, exporting `RTCLOK`, `SDMCTL`, `SDLSTL`, `SDLSTH` and `CH`. **Resident wherever the OS is used at all**, even in a Phase without the ROM, so that the OS finds its variables as it left them when a later Phase switches it back in; see 0051 and 0229. |
| `atari/osrom.asm` | The Atari OS ROM: two Sections that hold no bytes over `$C000-$CFFF` and `$E000-$FFFF` — the high one from `$E000` and not from `$D800`, the pack below it being `atari/mathpack.asm` — each `root`, exporting `SETVBV` and `XITVBV`. **A ROM the driver switches out**: listed as `resident`, so a Phase has it unless it says `without osrom`, and then it has the RAM underneath and no call into the OS — see 0229. |
| `atari/basic.asm` | The BASIC ROM at `$A000-$BFFF`, one Section holding no bytes. Listed by no variant: a program that wants BASIC lists it and names it in a Phase's `needs`, and where the driver declares `.driver rom basic` every other Phase runs with BASIC switched out. |
| `atari/mariacel.ngp` | An Atari 800XL holding a **MariaCEL** cartridge: an FPGA board on the parallel bus with a sprite blitter, a video output of its own and 32 MB of SDRAM behind two windows of sixteen kilobytes. Either window can show anything the board has, so the variant makes the choice a Window needs: `cel8000` shows the SDRAM and `cel4000` the blitter's five BRAM blocks, which is what the board's own programs do. The SDRAM is **2047 Banks**, blocks one to 2047, declared `linear $4000 .. $1FFFFFF` because the blitter reads them as one memory from `$4000` on, so a Pane's Section there has the address it reads a texture by (0251); block zero, what a RAMMAP of zero means, is the machine's own memory, which the board does not reach. A unit's number and a state of `cel8000` are two bytes. A program that wants SDRAM of its own declares fewer Banks and reaches the rest by writing `RAMMAP8000L/H` by hand. Neither window's range holds anything but a Pane or storage: `$8000-$BFFF` is in no Region, as a XEGS cartridge's window is, and `$4000-$7FFF` is inside `ram`, which the windows are taken out of. It declares the registers the board's example programs write and no more. Its Container is the `.xex` a DOS loads. Its Holders are the 800XL's (0248). |
| `atari/sdram.ngp` | Storage for `atari/mariacel.ngp`: the Banks of its unit set `sdram`, and `zx0` listed as `resident`. A Project includes it beside the machine. |
| `atari/mcel.asm` | The driver for that board: the two RAMMAP windows, and the SDRAM behind the one at `$8000` as storage. It declares **`init`** (0227) because the board answers at none of its addresses until `PDVREG` carries its identifier, so until then a write to RAMMAP is a write to nothing and nothing reports it. **One write and not the two the board's own loader makes**: the OS's shadow of that register is what lets a device's ROM, called by the OS, read back which device it is, and this board has no such ROM — it maps one page at `$DF00` and nothing at the `$D803`/`$D80B` the kernel's scan tests, so the scan never marks it and never calls it. The identifier is a **bit**, so a write deselects every other device on the bus. `finalize` puts both RAMMAP pairs back at zero, the machine's own memory, for a program that returns, and the OS ROM is its one ROM, bit 0 of PORTB, which `select` writes (0229); the floating-point pack is the parallel bus's and not its to switch. A state of `cel8000` is a Bank and the block is one more than it; the states of `cel4000` are a table and not arithmetic, since bit 7 of the high byte is what takes the window off SDRAM. Exports the `CELCTL` masks and the palette bank numbers, with the two rules that go with them — the obligatory level mask, and no read-modify-write. Needs the variant's Windows, its `register` list, a unit set `sdram`, and storage that is it wherever there is storage. |
| `atari/mceltables.asm` | The blitter's two input tables as Sections in the variant's Panes, everything in the Namespace `cel`. **The sprite list is addressed by page and not by record** — the field picks the page and the sprite's number the offset in it — so it is twenty Sections of 256 bytes and not one of 5120: a page is an address of the same kind as the window's own, and a program writes `sta cel.angle,x`. The twelve pages above `cel.opcode` are read differently for each opcode, so each carries a Label per reading and `cel.scaleXLo`, `cel.dstWLo` and `cel.euXLo` are one place; what a `union` is for, and here it is only several names. `cel.texTab` is one Section, record-major as the hardware has it. Each Pane pinned to the state of `cel4000` that shows it. Neither holds bytes and neither could — a Pane pinned to a named state has no loader to come from, and BRAM is not memory a Container writes — so the program fills them through the window. `root`, since the blitter reads them with no Reference; not `foreign`, since the CPU reads and writes every byte. Beside `sprList` stand the seven bytes the viewport and the collision scan answer at, which are registers of the blitter that happen to be inside a window rather than beside `CELCTL`, and are therefore here and not in the variant's `register` list. What a record holds is the board's documentation and is deliberately not repeated. |
| `atari/mathpack.asm` | The floating-point routines at `$D800-$DFFF`, as one Section holding no bytes. **A Module of its own and not part of `atari/osrom.asm`**, because it is the one range of the OS that something else may take away: a device on the parallel bus **may** map its ROM over the whole of it once selected — the kernel's own scan says so, and looks for the device's identifying bytes at `$D803` and `$D80B`. Whether a given board does, and over how much, is the board's; what follows for this file is only that the range cannot be claimed unconditionally. A variant whose PBI device is selected for the life of the program leaves this file out and says what stands there instead, which `atari/mariacel.ngp` does. On an XL the one bit of PORTB that takes the OS ROM out takes this out too, which `portb.asm` says with `.driver rom mathpack osrom`. Exports nothing: the pack's entry points are Atari's to document and nothing the tool ships calls one. |
| `atari/portb.asm` | The driver for extended memory behind `PORTB`: it streams through the variant's Window `ext`, shows a state of `ext` on request — the PORTB value per state is its own table, the four values of extended memory and then `$FF` for the machine's own, trimmed to the variant's `extension` by a macro, so that a state is a unit's number — and `copy` reads the window directly. Its roles are macros: `open`, `read`, `show` and `showAt` call a procedure each. **The same register holds the OS ROM and BASIC**, so it also declares `osrom`, `mathpack osrom` and `basic` as its ROMs and `select` writes their two bits for the Phase entered, which every switch of a Bank then keeps. `init` keeps the PORTB the program found and `finalize` puts it back, so a program that returns leaves BASIC as the user had it. Needs the variant's `register PORTB`, its Window `ext`, a unit set `extension`, and storage that is it wherever there is storage; a ROM whose Module the Project does not list is one no Phase of it has. |
| `atari/roms.asm` | The driver of an XL's ROMs and of nothing else: `osrom`, `mathpack osrom` and `basic`, which `select` writes as PORTB bits 0 and 1 for the Phase entered, keeping the rest of the register. `init` keeps the PORTB the program found and `finalize` puts it back; `mask` and `unmask` clear and set `NMIEN` around the load's move under a ROM. **It has no stream** — no `open`, `read` or cells — so it is a driver only in a program without storage, and `nga.open` and `nga.read` are refused where it is. Needs the variant's `register PORTB`. |
| `lynx/lynx.ngp` | An Atari Lynx, as the CPU sees it: 64 KB of RAM, the two pages Suzy and Mikey answer at, the boot ROM's range `reserved` and the four bytes above it that nothing reads left as memory, and 177 of the machine's registers by name. `cpu "65sc02"`, since the Rockwell bit instructions are the second revision's alone. No Window — nothing here is switched while it runs — and no storage, which a cartridge is and which `lynx/cart.asm` will reach. Why the map is taken to hold one value, and why the ROM is a Region and not a Module, is 0219. Its Holders are `irq` and `display` (0248). |
| `lynx/rom.asm` | The boot ROM's one entry this tool wants: `romSetPage = $FE00`, which shifts eight bits of `A` into the cartridge's address register and leaves the counter released. An address and a contract in a comment, as the Atari's `SETVBV` is — the ROM itself is the variant's `reserved` Region. |
| `lynx/screen.asm` | The buffer the display is given: 8160 bytes at `$E000`, `align 4`, `root`, `foreign`. It reaches `$FFDF`, through the pages the CPU reads as hardware and the display reads as memory, which is what `foreign` is for; the CPU reaches `$E000-$FBFF` of it and no Payload can land there. |
| `lynx/screen2.asm` | The second buffer, 8160 bytes at `$C000`, for a program that draws into one while the display reads the other. Wholly memory both masters agree on, so the CPU may write every byte and a Payload may land in it. |
| `lynx/collide.asm` | The buffer the sprite engine builds collisions in, 8160 bytes at `$A000`, `foreign` for the same reason and with no `align`, since it is the display address register alone that rounds an address down. |
| `pet/3032.ngp` | A Commodore PET 3032: a 6502, thirty-two kilobytes of RAM, the display's page at `$8000`, the I/O the IEEE-488 port is split across, and the three Modules below listed as `resident`. The ROMs are **`reserved` and not `rom`** — `rom` is where a Section of ours may stand, which is true of a cartridge and false of a machine whose ROM was in it first (0224). `$0200` to `$040D` stands in no Region: it is RAM, but RAM a `.prg` cannot carry, since `LOAD` puts the block at `$0401` and the line of BASIC that enters the program is there. Its Containers are the `prg` and the `d64`, which is the same program on a diskette whose other sectors a Transition reads. A Project gets the machine with `include "pet/3032.ngp"`. Its one Holder is `irq`, the vector `pet/kernal.asm` reserves (0248). |
| `pet/kernal.asm` | What the PET's ROM keeps in RAM, as Sections holding no bytes, and the addresses a program calls it at. This is a machine whose interrupt handler the program has taken over, so what is reserved is what the kernal's **disk path** touches — measured at twelve bytes of zero page, five of them the caller's own — and seven more the kernal's handler may write in the window between the `SYS` and the program's own `sei`. Every address is specific to `kernal-2.901465-03`; the bodies of `OPEN` and `CLOSE`, which machine code enters past the BASIC parameter parser, are published wrongly for other sets and land mid-instruction here. |
| `pet/screen.asm` | The display's memory: 1024 bytes at `$8000`, `root`, a thousand of them shown. Not `foreign`, unlike a Lynx's buffer — nothing of the hardware answers at these addresses, so the CPU may write every byte. The Label is `screenRam`, since `screen` is the name of the Charset these bytes are read as. |
| `pet/charsets.asm` | The PET's two codes for the same letters, as Charsets: `petscii`, what the ROM's character output takes, which over the range a program prints is ASCII but for the pound sign and the two arrows; and `screen`, what the video circuit reads out of the display, where `@` is zero and a letter is not what ASCII makes it. The **graphics halves are not written**: each would have to be read off the character generator and matched to the Unicode its glyph is drawn as, as the Atari's was, and until then a literal of one is refused by name. Emits nothing. |
| `pet/disk.asm` | The driver for a Commodore diskette, which the program reads over the IEEE-488 bus itself. A unit is a **track** and the offset's high byte is the sector, so the three bytes the model addresses storage with are the two numbers `U1` takes and `open` does no arithmetic on them. It says `.driver span none`, so nothing ever crosses a track and it needs to know **nothing** of the surface: not which tracks are long, not where the directory is, not which track follows which. The OPEN sequence is by hand — the ROM's own begins with the BASIC parameter parser, which reads its arguments out of BASIC text — success is read from the count of open files at `$AE` and not from the carry, and EOF is bit **6** of `STATUS`. The data path is the ROM's handshake with the timeout, the EOI test and the channel dispatch taken out. Names no Window, so `stream`, `show` and `showAt` are not declared. |
| `pet/d64.ngp`, `pet/d80.ngp`, `pet/d82.ngp` | Storage on a diskette of that surface: 36 units of 5376 bytes, 78 of 7424 or 155 of 7424, the driver above and `zx0`. The unit's number is the track's, so unit zero is no track, the directory's track is the disk's and — on the larger two — so is the track its map has to itself. `size` is the **widest** track and therefore a stride, since what a narrower one does not have is held against every image. A Project includes the one whose surface it named in `container`, and the two are checked against each other (`NGA1238`). |
| `lynx/cart.asm` | The driver for the cartridge, which is the one medium here that is not in the address space: a page is shifted into an address register eight bits at a time and a counter walks it, so there is no Window and `stream`, `show` and `showAt` are not declared. A unit of storage is a **page** and the model's unit *i* is page *i+1*, page zero holding the bootstrap — a constant this file and the Container both hold, as the diskette's sector four is. It says `.driver seek forward`, an offset being reachable only by reading up to it, and `open` therefore reads on from where the stream stands wherever the page is the one wanted and the offset is ahead of it. An offset past the page's end is carried into the pages after, as every driver here carries one past its unit. Needs `lynx/rom.asm` for the routine that shifts a page in, and one of the four documents below for its page size. |
| `lynx/cart64k.ngp`, `lynx/cart128k.ngp`, `lynx/cart256k.ngp`, `lynx/cart512k.ngp` | Storage on a board of that size: 255 units of its page, the driver, and `zx0`. A Project includes the one whose geometry is the board it names in `container`, and the two are checked against each other (`NGA1237`). |
| `lynx/screen.ngp`, `lynx/screens.ngp` | One display buffer, or two, under the one name `screens` — so that a Project changes how many it has by changing which document it includes. **Include one of the two and never both**: they declare the same Module, and twice over it is the same Section twice. |
| `stream/rle.asm` | The `rle` decoder over a driver's stream, read through `nga.read`. |
| `stream/zx0.asm` | The `zx0` decoder over a driver's stream, read through `nga.read`. |

Every file here is held to what it claims by the test suite of the repository
it is developed in: the Container built with it is loaded into a machine and
every Transition it takes is run on a 6502.
